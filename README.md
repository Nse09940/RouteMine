# RouteMine

RouteMine — Android-приложение для распределения заказов между курьерами и построения удобных маршрутов.

Диспетчер добавляет доставки и отмечает доступных курьеров. RouteMine предлагает, кому передать каждый заказ и в каком порядке посетить адреса. Курьер получает готовый маршрут, забирает посылки и отмечает их вручение.



## Зачем нужен RouteMine

Когда заказов мало, диспетчер может распределить их вручную. Но с ростом числа адресов становится сложно быстро решить:

- какой курьер должен взять заказ;
- в каком порядке посещать точки;
- успеет ли курьер в указанный интервал;
- поместятся ли все посылки в его транспорт;
- как сократить лишние поездки и опоздания.

RouteMine берёт эти расчёты на себя, а окончательное решение оставляет диспетчеру.

## Кто пользуется приложением

В приложении две роли: диспетчер и курьер. Отдельного кабинета клиента или получателя нет.

### Диспетчер

Диспетчер организует доставку:

- создаёт и редактирует заказы;
- указывает точки забора и вручения;
- добавляет информацию о посылке и получателе;
- задаёт желаемое время доставки;
- видит доступных курьеров;
- запускает построение маршрутов;
- проверяет и подтверждает результат;
- при необходимости назначает заказ вручную;
- следит за выполнением;
- просматривает историю заказов.

### Курьер

Курьер работает с уже назначенными доставками:

- начинает и завершает смену;
- отмечает, что готов принимать заказы;
- получает маршрут;
- видит следующую остановку и весь список точек;
- открывает адрес в навигаторе;
- подтверждает забор посылки;
- подтверждает вручение кодом получателя;
- сообщает, если забрать или вручить посылку не удалось;
- просматривает завершённые доставки.

Получателю не нужно устанавливать приложение. Его имя, телефон и код вручения хранятся в заказе. Код передаётся получателю заранее вне RouteMine.

## Как проходит доставка

```text
Диспетчер создаёт несколько заказов
              ↓
Отмечает доступных курьеров
              ↓
RouteMine предлагает распределение и маршруты
              ↓
Диспетчер проверяет и подтверждает план
              ↓
Курьеры получают свои маршруты
              ↓
Забирают и доставляют посылки
              ↓
Диспетчер видит актуальные статусы
```

## Основные экраны

### Для диспетчера

- главная страница со сводкой;
- список заказов;
- создание и редактирование заказа;
- список курьеров;
- экран распределения заказов;
- маршруты на карте;
- наблюдение за выполнением;
- история доставок.

### Для курьера

- управление сменой;
- текущий маршрут;
- список остановок;
- карточка забора или вручения;
- сообщение о проблеме;
- история выполненных маршрутов.

## Что хранится в заказе

- адрес и точка забора на карте;
- адрес и точка вручения;
- имя и телефон получателя;
- описание, вес и размеры посылки;
- допустимое время забора и доставки;
- код подтверждения;
- текущий статус;
- назначенный курьер;
- история изменений.

## Статусы заказа

Обычная доставка проходит следующие этапы:

```text
Создан → Планируется → Назначен → Курьер едет за посылкой
       → Посылка забрана → В пути → Доставлен
```

Если что-то пошло не так, заказ можно отменить, отметить неудачный забор или неудачное вручение и оформить возврат отправителю.

RouteMine не позволяет пропускать обязательные этапы. Например, нельзя вручить посылку до того, как курьер подтвердил её забор.

## Как строится маршрут

У каждого заказа есть две связанные точки: сначала посылку нужно забрать, затем доставить.

При распределении заказов RouteMine учитывает:

1. порядок забора и вручения;
2. доступность курьеров;
3. вместимость и тип транспорта;
4. время работы курьера;
5. допустимые интервалы доставки;
6. время на каждой остановке;
7. расстояние между точками;
8. общий пробег и возможные опоздания.

Например, маршрут одного курьера может выглядеть так:

```text
Забрать заказ №1
        ↓
Забрать заказ №2
        ↓
Доставить заказ №1
        ↓
Забрать заказ №3
        ↓
Доставить заказы №2 и №3
```

Сначала маршруты строятся целиком до начала поездки. Перестроение активного маршрута при появлении новых заказов можно добавить позднее.

## Серверная часть

В репозитории реализован backend RouteMine в виде модульного монолита. Это одно запускаемое приложение с общей базой данных, но бизнес-функции разделены на самостоятельные модули:

```text
identity    — пользователи, роли и вход в систему
couriers    — курьеры и смены
deliveries  — заказы, статусы и история
dispatch    — ручное назначение
routing     — расчёт, подтверждение и выполнение маршрутов
```

HTTP-обработчики отвечают только за приём и проверку запросов. Правила доставки находятся в бизнес-моделях и сервисах, а работа с базой данных и расчёт расстояний подключены через отдельные интерфейсы.

### Что уже работает

- вход диспетчера и курьера с выдачей токена;
- разграничение операций по ролям;
- создание курьера вместе с его учётной записью;
- открытие и закрытие смены;
- создание, просмотр и отмена доставки;
- ручное назначение заказа доступному курьеру;
- построение маршрута для одного курьера и нескольких заказов;
- проверка грузоподъёмности на каждой остановке;
- обязательный забор посылки перед её вручением;
- подтверждение маршрута одной транзакцией;
- защита от повторного и конкурентного назначения;
- выполнение маршрута и проверка кода вручения;
- проверка порядка остановок и фактической нагрузки при выполнении доставки, включая одновременные запросы;
- блокировка ввода кода вручения на 15 минут после пяти неверных попыток;
- история изменения статусов;
- единый формат ошибок и интерактивная документация API.

Маршрут строится не более чем для восьми заказов. Сервер перебирает допустимые последовательности остановок и выбирает кратчайшую. Сейчас расстояния рассчитываются между географическими координатами и не учитывают дорожную сеть. Источник расстояний отделён интерфейсом, поэтому позднее его можно заменить на дорожный сервис без изменения правил маршрутизации.

Курьер выполняет остановки в порядке маршрута после его запуска. Отменённые заказы и неудачные заборы пропускаются. При ручных назначениях проверяется фактический груз; новый маршрут нельзя создать или подтвердить до завершения всех ранее назначенных доставок.

Неверные коды вручения учитываются в базе данных. Первые четыре ошибки возвращают HTTP 409, пятая блокирует проверку на 15 минут с HTTP 429; во время блокировки правильный код также не принимается.

## Запуск

Для запуска нужны Docker Desktop и Docker Compose.

Сначала создайте локальный файл с параметрами окружения:

```powershell
Copy-Item .env.example .env
```

Замените значения в `.env` на свои. Значение `JWT_SECRET` должно содержать не менее 32 символов. Файл `.env` исключён из Git.

Запустите приложение и PostgreSQL:

```powershell
docker compose up --build
```

После запуска доступны:

- API: `http://localhost:8080/api/v1`;
- Swagger UI: `http://localhost:8080/swagger-ui.html`;
- OpenAPI: `http://localhost:8080/v3/api-docs`.

При первом запуске создаётся диспетчер с логином и паролем из `.env`.

Остановить приложение:

```powershell
docker compose down
```

Чтобы также удалить локальные данные PostgreSQL:

```powershell
docker compose down --volumes
```

## Проверка

Модульные и интеграционные тесты запускаются командой:

```powershell
.\gradlew.bat test
```

Интеграционный тест использует настоящую PostgreSQL в одноразовом контейнере, поэтому перед запуском тестов Docker должен быть включён.

Тесты проверяют:

- допустимые переходы статусов доставки;
- запрет пропуска обязательных этапов;
- порядок забора и вручения;
- ограничение грузоподъёмности;
- применение миграций;
- авторизацию и права ролей;
- полный сценарий от создания заказов до завершения маршрута;
- запуск маршрута и соблюдение порядка остановок;
- запрет перегруза при конкурентных заборах;
- конфликт ручного назначения с подтверждением маршрута;
- сохранение счётчика неверных кодов и снятие блокировки после её истечения;
- корректные HTTP-статусы при отказе по роли и неверных параметрах.
